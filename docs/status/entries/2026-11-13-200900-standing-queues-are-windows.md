Measured correction to the loose explanation: in Chromium a clipping ancestor that is **itself captured** does report `scrollWidth > clientWidth`, `overflow: clip` included — the real blind spot is a clipping ancestor **outside the captured subtree**, plus left/top/bottom clipping, which a right-edge check never looks at. New gate-eligible `clipped_by_ancestor` (P1) compares an element's box with its clipping ancestor's on all four sides; 1 px tolerance, scroll containers and `fixed` skipped, children deduped against an overhanging captured parent. Fixture asserts the OLD classes report zero first, so the control is that the bug escapes the old lens. Not covered: `clip-path`, `contain: paint`, `html`/`body` overflow. `--gate` is drift-only, so an existing consumer needs `--update-baseline` for clips it already has.
