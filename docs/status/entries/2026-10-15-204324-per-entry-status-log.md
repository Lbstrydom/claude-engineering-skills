## 2026-10-15 — fleet chips theme PR 2b: the session log as one file per entry (p-20261015060430-76b2, p-20261015160944-2551)

**Why.** `status.md` conflicted four times in one day once PR 1 removed the other two conflict files: every `/ship` inserted its entry at the top of one file, so two concurrent ships always collided, and each collision cost a re-merge, a re-push and a gate slot. GitHub ignores `.gitattributes` merge drivers and runs no CI on a CONFLICTING PR, so the fix had to remove the shared path, not resolve it.

- **A new entry is a new file**: `docs/status/entries/<YYYY-MM-DD>-<HHMMSS>-<slug>.md` (this very entry is the first). The first line is the entry's own `## YYYY-MM-DD — summary` heading, so `grep -rn '^## 2026-10-15' status.md docs/status/` still finds it. `status.md` stays as frozen history: no rendering, no generated artifact, no reader needs a build step.
- **One marker, one resolver**: `docs/status/entries/README.md` switches per-entry mode on; `perEntryMode` in `scripts/lib/status-entry-files.mjs` is the only place that says so (the gate, the dashboard reader and `/ship`'s instructions all follow it). A consumer has no marker, so its `/ship` keeps appending to `status.md` unchanged.
- **Gate Laws 6-9** (`scripts/lib/status-log-integrity.mjs`, `npm run status:integrity:gate`): the root gains no new heading (`root-entry-added`, with a span-aware recipe in the message), entry records are immutable and conserved, new records are well-formed, and the marker itself cannot be deleted. A directory of entries with no marker, and any foreign file in it, are named rather than read as "no entries".
- **The marker is a regular file everywhere** (lstat on disk, ls-tree mode in a snapshot); a directory or symlink named `README.md` neither switches the mode on nor hides.
- **Absence is not failure**: a failed `git ls-tree`, an unreadable entries directory or marker now fail the gate (exit 2) instead of reading as an empty baseline; only ENOENT means "legacy". The old `archivesAt` had the same shape and was fixed with it. `docs/status/README.md` (the index) was being read as a frozen archive and could not be edited at all; it is no longer.
- **Readers**: the dashboard's shipped log and Backlog trend read entry files newest-first and then the `status.md` head through one function, with an honest `capped` flag, and only in marker mode.
- **Audit**: `/audit-code`, 6 rounds on this PR. R1 (4 HIGH / 7 MEDIUM) was mostly one root cause (failures represented as absence) plus the marker deciding the reader's mode; R2-R4 each found one real edge in the marker policy (a directory named README.md, a stat failure read as absent, a symlink); R5 and R6 clean. Gemini APPROVE, 0 blocking, 0 debt. One MEDIUM deferred with a rationale (the gate loads every entry's content at both ends; revisit at 500 files, plan section 12.5).
- **Evidence**: seven of the new law and reader tests were seen red against a mutated lib, then green; the merge test is its own negative control (the old flow conflicts under `git merge-tree`, the new one merges cleanly and passes the gate); every merge test builds its own repository. `guards:preflight` PASS.
- **Rollout**: branches that already added a root entry will trip `root-entry-added` once; the message carries the recipe (move only your added block into a new entry file, keep legitimate amendments to older entries). The coordinator should announce it.
