## 2. Design

**Right-sizing.** Band-aid: add the columns and stop — nothing would notice a column that never fills (that is how `adjudicator_kind` sat 97% null). Over-built: a generic provenance framework or a warehouse. Chosen: add only columns that have a writer in this PR, stamp the cheap ones centrally at the one seam that sees every row, and add the drift-only null-rate gate that makes any column that stops filling visible. No column ships without a writer and a coverage entry.

Decisions:

1. **One migration** `20261028120000_own_model_telemetry_pr3.sql`, additive and idempotent:
   - `learning_decisions`: `tool_sha text`, `policy_version text`, `schema_version int`, `selection_rule text`, `selection_probability numeric`, `randomised boolean`, `input_snapshot jsonb`, `options_not_chosen jsonb`, `eligible_population int`. (rows 2, 3, 4, 6, 11)
   - `audit_runs`: `tool_sha text`, `policy_version text`. (row 6)
   - `finding_adjudication_events`: `ingested_at timestamptz NOT NULL DEFAULT now()` and `ingested_at_inferred boolean NOT NULL DEFAULT false`. Existing rows are backfilled `ingested_at = created_at, ingested_at_inferred = true` (there is no record of true receipt time for history, and the flag says so; new rows are observed, `false`). Event time stays `created_at`. View `finding_label_history` (finding_id, outcome, state, created_at, ingested_at, ingested_at_inferred, ordinal) is the label source of truth. (row 1)
   - `audit_repos`: `training_eligibility_approved_by text`, `training_eligibility_set_at timestamptz`. New append-only `training_eligibility_events` (repo_id, eligible, reason, approved_by, set_at, ingested_at) so consent history is never overwritten. (row 12)
   - New `llm_call_provenance` (row 5): `call_id uuid PRIMARY KEY` (deterministic UUIDv5 of `run_id|producer|process_nonce|seq`, so a replayed spill collapses and two processes cannot collide), audit_run_id, repo_id, work_item_id, producer (`audit`|`final-review`), purpose, model_resolved, route (`native|openrouter|azure|cli`), prompt_hash, prompt_variant, temperature, reasoning_effort, input/cached/output/reasoning tokens, latency_ms, cost_usd, truncated, retried, fallback, created_at, schema_version. Identity is `call_id` alone.
   - New `llm_call_log_summary` (audit_run_id, producer, process_nonce, recorded int, dropped int, PRIMARY KEY (audit_run_id, producer, process_nonce)): one row per producing process, so two producers on one run never overwrite each other's counts.
2. **Central stamping** (`recordDecision`): `tool_sha` (git HEAD of the running tree, or the sync-manifest source commit for a consumer bundle), `policy_version` (first 16 hex of the sha256 of AGENTS.md, hashed once per process), `schema_version` are added to every decision entry by one helper `scripts/lib/telemetry/provenance.mjs`, so callers cannot forget them; `insertLearningDecision` writes them. Callers MAY add `selection_rule`, `selection_probability`, `randomised`, `input_snapshot`, `options_not_chosen`, `eligible_population`; the `pass_selection` caller (`legacy-production-audit.mjs:494`) is wired as the first real producer (rule `all-passes`, probability 1, randomised false, `options_not_chosen` = skipped passes, `eligible_population` = pass roster size, `input_snapshot.diff_hash` from the audited tree when known). `input_snapshot` is validated by `normalizeSnapshot` (provenance.mjs): ALLOWED keys are `diff_hash`, `prompt_hash`, `state_hash` (each a lowercase hex string of 8 to 64 characters) and `precedent_ids` (at most 20 strings of 1 to 64 characters from letters, digits and `_ . : -`); unknown keys are dropped and counted, a result over 2 KB is rejected. The content-free promise is therefore executable, not a convention.
3. **Run stamping**: the `audit.convergenceState` state gains `tool_sha`, `policy_version`; `recordConvergenceState` allowlists them (well-formed shape only).
4. **LLM call log**: `scripts/lib/telemetry/llm-call-log.mjs` is a module-level singleton, one per process, owned by the entry point. `bindRun({runId, repoId, workItemId, producer})` is called by `legacy-production-audit.mjs` right after `recordRunStart` returns the run id (producer `audit`) and by `scripts/gemini-review.mjs` after it resolves its run id (producer `final-review`); unbound means `record()` is a counted no-op, never a guess. `callGPT` calls `record({purpose, model, route, promptHash, promptVariant, temperature, reasoningEffort, usage, latencyMs, costUsd, truncated, retried, fallback})` once per accepted call (never content); the log assigns `seq` from a process-local counter and a per-process random nonce, and derives `call_id` as above. The log is flushed once at finalisation through a new registered writer `audit.llmCalls` (`rowKey` = `run_id:producer:nonce`; one transaction inserts the call rows `ON CONFLICT (call_id) DO NOTHING` and upserts its own `llm_call_log_summary` row). The Gemini CLI flushes its own producer through the same writer at exit. Buffer cap 500; overflow drops the oldest and counts `dropped`. **Loss is reported**: `dropped > 0` makes the flush return `lost` (run `incomplete`) and the summary row preserves the counts, so a surviving subset can never read as a complete log.
5. **Label history**: `recordAdjudicationEvent` already appends; it relies on the `ingested_at` default. `finding_label_history` is the documented reader; `user_action` stays deprecated.
6. **Consent lineage**: `setTrainingEligibility` also appends a `training_eligibility_events` row and stamps approver/time on the repo row in ONE transaction. `--approved-by` is required (a flag that changes the corpus must name who); absent means refuse.
7. **Null-rate coverage gate** (row 11): `scripts/own-model-coverage.mjs`, pure core `scripts/lib/telemetry/coverage.mjs`. Tracked set = committed `.own-model-coverage.json`, entries `{table, column, since, where?, expectFill, tolerance}`. `where` is a key into a closed enum of applicability predicates (each a fixed SQL fragment in code, never user text) so an optional field is measured only over rows that CAN fill it; `expectFill` is a **hand-set floor** per entry (never auto-seeded from an observed zero) for rows created at or after `since`. Modes: `snapshot --out f` (dated per-column rates, counts only); `check --static` (offline, run in `check` as `npm run own-model:coverage:gate`: every entry names a column present in the schema fixture, every column added by this PR's migration has an entry, `where` keys are in the enum; exit 0 or 1); `check --live` (store; per-column status `ok | drift | below-floor | unmeasured:no-eligible-rows | unmeasured:store`; JSON envelope on stdout; exit 0 all ok, 1 any drift or below-floor, 3 any unmeasured). Drift-only: fails when a column's post-`since` rate falls more than `tolerance` below its committed baseline OR below `expectFill`. Zero eligible rows is `unmeasured`, never green. The live check runs from the local weekly maintenance replica because the store is not reachable from Actions; maintenance treats exit 3 as a warning line and exit 1 as a failure.
8. **Transcript archive** (the "history that dies" action): `scripts/transcript-archive.mjs`, pure core `scripts/lib/telemetry/transcript-archive.mjs`. Input: an exported transcript file path + `--repo`, `--coordinator`, `--date`. Looks up the repo flag. `true` means secret-redact (`redactSecrets`, refuse on a surviving `scanForSecrets` hit) and store; `false` or `unknown` means NO content stored, only a manifest row with `content_state:'structure-only'` and the sha256 (storyline is therefore never archived). Layout: `<dir>/blobs/<repo-slug>/<sha256>` (blobs are per repo, never shared across repos, so purging one repo cannot remove another's blob) and `<dir>/manifest.jsonl`, with `<dir>` = `AUDIT_TRANSCRIPT_ARCHIVE_DIR` (default `~/.audit-loop/transcript-archive`, outside the repo, owner-only permissions where the OS supports them). Protocol: take an exclusive lock file (`O_EXCL`, stale after 10 minutes), write the redacted blob to a temp name and rename it into place, THEN append the manifest row; `purge --repo` takes the same lock, deletes that repo's blob directory, then rewrites the manifest without those rows by temp+rename. A crash between steps leaves an orphan blob or a manifest row without a blob; `verify` reports both and `verify --repair` removes orphan blobs and marks dangling rows, so no state is silent. Off-machine durability is Louis's backup decision and the doc says so.
9. **Dated baseline**: `node scripts/own-model-coverage.mjs snapshot --out docs/research/own-model-null-rate-baseline-2026-10-27.json` run against the NAS store for the three memo tables (`learning_decisions`, `finding_adjudication_events`, `fleet_events`), counts and rates only, committed. The floors for the new columns in `.own-model-coverage.json` are set by hand from what each writer guarantees (stamped columns 0.99 for new rows, `pass_selection`-scoped columns 0.95).
10. **Back-populate** (memo third bullet) is NOT done blindly: the census already reports `audited_sha`/`fix_commit_sha` fill; a bulk git back-fill mutates historical rows store-wide and is a named follow-up (independent: nothing here reads backfilled values).
