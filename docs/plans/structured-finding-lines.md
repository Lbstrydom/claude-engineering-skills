# Plan: structured line anchors on audit findings, so the T2 `reopenRate` signal becomes measurable
- **Date**: 2026-11-23
- **Status**: In progress — plan audited 2026-11-23 (3 GPT rounds, Gemini APPROVE); implementation autonomous, no push, no PR
- **Author**: Claude + Louis (Louis approved the prompt change now, not after Pilot 1)
- **Scope**: backend (stack `js-ts`): `scripts/lib/schemas.mjs`, `scripts/lib/prompt-seeds.mjs`, a new `scripts/lib/audit/finding-lines.mjs`, one call in `scripts/lib/audit/finding-assembly.mjs`, tests
- **Builds on**: `docs/plans/meta-step-back-at-cap.md` (T2 trigger), the 2026-11-23 T2 investigation, `docs/plans/seeded-defect-benchmark.md` (Pilot 1)
- **Draft origin**: coordinator session `local_04ff9953`, `ces-structured-finding-lines-plan-2026-11-23.md` (options A/B/C and the recommendation are kept below)

Neighbourhood considered: `get-neighbourhood` is run at implementation time for the one new module (resolver). Existing precedent found by reading, not by embedding: `evidence-triage.mjs`'s `findQuoteLineInHunk`/`resolveAnchorLocation` (tiered pipeline: a model quote is resolved to a verified line) and `round-signals.mjs` `citedLocation`.

---

## 1. Problem (measured, 2026-11-23)

`reopenRate(N)` needs, per finding, a file and a cited line range. Live findings carry `_primaryFile`/`affectedFiles` and no line field; 27 of 3,120 (0.9%) cite a usable `file:N` in prose. At checkpoint 3 the signal is therefore "unmeasured" in practice: never fires, never quiet. Positive control that the signal itself works: git range `66b91739..c2d62f6b`, `scripts/lib/llm-budget.mjs`, findings with lines inside real hunks give `measured: true, value 0.667, fires: true`; the same findings with no line give `measured: false`.

## 2. The seam, and two facts the draft did not have

- Producer contract: `ProducerFindingSchema` (`scripts/lib/schemas.mjs`), spread from `FindingBase` and handed to OpenAI via `zodTextFormat` and to Gemini via `zodToGeminiSchema` (final review `.extend`s it). Persisted shape: `PersistedFindingSchema` (non-strict `z.object`: an undeclared key is STRIPPED on parse).
- Consumer: `citedLocation()` in `scripts/lib/audit/round-signals.mjs` already reads `f.line`, `f.lineStart/lineEnd`, `f.lines`, then falls back to `file:N` in `section`/`detail`. **Its contract does not change.**
- Identity: `semanticId()` hashes `category|section|detail` only; `generateTopicId` hashes file|principle|category|pass|`_hash`. Neither can see a new field, so `_hash`, topic ids and ledger suppression are unchanged by construction. A test pins it (section 6). `section` must NOT be rewritten to carry a line (it is inside the hash).
- **Fact 1: the model is not shown line numbers.** `readFilesAsAnnotatedContext` renders `//`-marker (block style) for every source language, and the default R1 `readFilesAsContext` render is plain text. Only the header-only style (non-source files) and the hunk-window render add a `NNNN | ` gutter. A prompt that says "give the first line number" therefore asks the model to COUNT lines in an un-numbered block: the draft's option B as written yields confident, plausible, wrong numbers.
- **Fact 2: a model-self-reported line was already rejected once.** The `FindingBase` docstring (decided 2026-07-26) records why: no way to tell a correct claim from a hallucinated one, evidenced by a one-line-off model claim. That reasoning stands; it is why section 4 recommends a *verified* line, not a self-reported one.

## 3. Options

- **A. Deterministic extraction only.** At persist time parse `file:N[-M]` from `section`/`detail` into `lineStart`/`lineEnd`. No model-visible change. Ceiling: the 0.9% that already cite lines. Rejected as the fix, kept as a no-op: `citedLocation` already does this read-side fallback, so persisting it adds a second spelling of the same predicate and nothing measured.
- **B. Model-supplied optional fields.** Optional `lineStart`/`lineEnd` on `ProducerFindingSchema`, asked for in the pass prompts, persisted on `PersistedFindingSchema`. Optional so every non-LLM constructor and old row stays valid. Problem per Facts 1 and 2: the model counts un-numbered lines and nothing checks it.
- **C. B plus validation.** Null a line that falls outside the file at the audited tree. Cheap form: range check only. Catches out-of-range hallucination, not off-by-N or off-by-hunk.

### Recommendation: B, with C strengthened from a range check to quote resolution

The model is asked for one **verbatim quote** of the code the finding is about (it copies text, which it does well, instead of counting lines, which it does badly); code resolves the quote to `lineStart`/`lineEnd` against the file the model saw. The model never emits a line number.

| | band-aid | over-built | this plan |
|---|---|---|---|
| shape | range-check a model-counted line (C cheap form) | add a `NNNN \|` gutter to every audit prompt, or run the tiered pipeline's diff-anchor machinery on the legacy path | one optional quote field + one pure resolver |
| why not | an in-range wrong line is a false hit in a signal that gates a paid reviewer | changes the whole code input of every pass (cost, cache prefix, +7 chars/line) for one optional field | smallest thing that makes the line **verified** and **file-relative** (never diff-hunk-relative) |

Lines are post-change FILE lines by construction: the resolver reads the working-tree file the audit rendered, so Risk 4 (diff-hunk numbers) cannot occur, and `reopenRate` already maps round N's lines against the post-image hunks of `auditedSha(N-1)..auditedSha(N)`. The prompt says "quote the line as it appears in the file, never a diff line (no leading `+`/`-`)".

## 4. Design

1. **Schemas** (`scripts/lib/schemas.mjs`): `FindingBase` untouched. `ProducerFindingSchema` gains `lineQuote: z.string().max(400).nullable().optional()` (1-3 consecutive source lines joined by `\n`, verbatim). `PersistedFindingSchema` gains `lineQuote` (same), `lineStart`/`lineEnd`: `z.number().int().positive().nullable().optional()`. The `FindingBase` docstring's DELIBERATELY-NO-LINE paragraph is rewritten: the decision stands for a self-reported number, and the new field is a quote verified by resolution. Fallback if the emitted-schema test (section 6) shows Gemini's `zodToGeminiSchema` or OpenAI strict mode rejecting nullable-optional here: add the field with `.extend` at the pass call sites (`legacy-production-audit.mjs`, `map-reduce-scheduler.mjs`) instead of on the shared schema.
2. **Resolver** `scripts/lib/audit/finding-lines.mjs` (pure; file text injected by the caller): `resolveFindingLines(finding, { readText })` returns `{ lineStart, lineEnd, status }`, `status` in `anchored | no-quote | no-file | not-found | ambiguous`. Match is EXACT per line after ONE normalisation: CRLF to LF. No trimming, no whitespace folding: whitespace can be string-literal content (template literals), and a tolerant match could equate two different lines. The prompt tells the model to copy the line exactly as shown, including leading indentation; a quote that drops indentation is `not-found` and the `[lines]` mix measures how often (an indentation-tolerant rule would need a syntax-aware design and is out of scope). A quote is 1-3 consecutive lines; a quote the model truncated mid-line or paraphrased simply does not match. **Unique match or null**: ambiguous and not-found are "unlocated", never a guess. **Which file**: only `_primaryFile`; a quote that lives in another file of a multi-file finding is `not-found` (unlocated), never searched across `affectedFiles`. A **round-scoped snapshot reader** loads each eligible path once per run, compares it to its audited-commit blob once (one `git show` per distinct path, not per finding), caches `{text|status}` per path for the run's lifetime only (bounded by the finding-primary-file set, discarded at run end, never shared across rounds), and every finding on that path reuses it (tested: three findings on one file cause one read and one blob lookup; a second round starts empty). Reads go through `safeReadFile` from `audit-scope.mjs` (repo containment after symlink resolution, sensitive-file refusal); a sensitive file, a path escaping the repo (lexically or via symlink), a path not rendered to the model this round, or any read error is `no-file` (fail closed).
   **Snapshot contract**: the signal interprets a line against `auditedSha(N)`, so a line is only valid when the text the resolver reads IS that commit's content. The resolver anchors only when the file's working-tree text is byte-equal (after the CRLF fold) to `git show <auditedSha>:<path>`; a file dirty relative to the audited commit is status `dirty` (unlocated), and a missing audited sha or blob is `no-basis` (unlocated). It therefore never invents a line for code that no commit-range measurement could map. The cost is honest: audits run on an uncommitted tree anchor fewer findings, and the `[lines]` mix (`dirty` count) says how many. Resolution runs in the same process, in the same round, before any later edit, so the file cannot change between render and resolve except by a concurrent writer, which the byte-equality check against the commit catches.
   **Provenance and precedence**: the resolver is the sole writer of `lineStart`/`lineEnd` for LLM-pass findings (the producer schema cannot emit them). It writes the pair atomically, and on any non-anchored status it clears both (null), so a stale or partial value from a re-used object never reaches `citedLocation`. Tool/linter findings that carry their own `file:line` in `section` are not touched. `lineEnd = lineStart + quoteLines - 1`.
3. **Wiring** (`finding-assembly.mjs`): one call in the existing `populateFindingMetadata` loop slot (after `_primaryFile` exists, before `suppressReRaises`), applying the 4.2 precedence to every LLM-pass finding (identified by `_pass` being one of the five LLM pass names; tool/mechanical findings are skipped): replace the pair on `anchored`, clear both on every other status, so a reused object with a stale or partial value is overwritten (tested with stale, partial and conflicting fixtures). It never touches `section`/`detail`/`_hash`. One stderr line per run: `[lines] N findings: anchored a, no-quote b, not-found c, ambiguous d, dirty e, no-basis f, no-file g`. This is a resolver COVERAGE count, separate from the signal's status: zero anchored is reported as a count, while `reopenRate` stays `measured: false` ("cite no lines") exactly as today; a test asserts both, plus that the prose `file:N` fallback still works.
4. **Prompt** (`scripts/lib/prompt-seeds.mjs`): one shared `LINE_ANCHOR_BLOCK` constant appended to the LLM pass seeds that emit `ProducerFindingSchema` findings (structure, wiring, backend, frontend, sustainability); the mechanical waves (`MECHANICAL_WAVES` in `audit-shadow.mjs`) are not touched and stay out of the paid shadow comparison. Text: set `lineQuote` to the exact source line (up to 3 consecutive lines) the finding is about, copied as it appears in the file after the change, no diff markers and no line numbers; null when the finding is not about specific code (missing feature, plan-level concern) OR when the relevant line is longer than 400 characters (a quote must be complete to match; never truncate). Tests: a 400-char quote parses, a 401-char one is rejected by the schema, and an over-long source line resolves to `no-quote`. A SEED edit is a global rollout (see section 5).
5. **Not changed**: `citedLocation`, `round-signals.mjs`, `meta-review.mjs` (PR (1) on `claude/ces-t2-observability-retired` owns those), the store schema (the live `reopenRate` reads local round result JSON; adding store columns is a separate migration decision), the Pilot 1 parked branch.

## 5. Risks, settled here

1. **Global prompt rollout.** Every audit gets the new block. Mitigations: optional field (null is a valid answer, so no new failure mode); the system prompt changes once (one cache-prefix cold start); the measurement in section 6 runs BEFORE this is called done; rollback is deleting one constant, since the schema field is inert when unasked.
2. **Identity drift.** Pinned by test: `semanticId` and `generateTopicId` of a finding are identical with and without `lineQuote/lineStart/lineEnd`.
3. **Stale lines across rounds.** The line is relative to the file the round saw; `reopenRate` already maps it through the round's own `auditedSha` range. Unchanged.
4. **Quote of redacted or truncated code.** A `[REDACTED...]` span or a head-cut file simply fails to resolve: `not-found`, unlocated.
5. **A resolved line that is "right" but about the wrong thing.** The quote is what the model said the finding is about; the resolver verifies the text exists at that place, not that the finding is correct. Same trust level as `section`.
6. **Gemini final review inherits the schema** through `.extend`; its prompt does not ask for the field, so it stays null. Covered by the emitted-schema test.

## 6. Verification

No-spend (part of the build, in `npm test`):
- **Real wiring, offline** (H4): representative provider responses (one legacy pass, one map-reduce pass) are pushed through production parsing, `addFindings`, `populateFindingMetadata`, the resolver, local round-result serialisation, reload, and `computeRoundSignals`; includes an old row without the fields and a non-LLM (tool) finding. The plan's pass list is verified against the code that attaches `PASS_PROMPTS` and `ProducerFindingSchema` together (`legacy-production-audit.mjs`, `map-reduce-scheduler.mjs`); a pass whose prompt asks for the field while its schema is a different one fails the test.
- **Emitted schema, not Zod source**: `z.toJSONSchema(ProducerFindingSchema)` has `lineQuote` in `properties`, not forced into `required` except where the provider dialect demands it; the actual `zodTextFormat(...)` JSON schema and `zodToGeminiSchema(...)` output are asserted field by field (required list, nullability dialect, the inherited `FinalReviewFindingSchema`), and a sample provider response with `lineQuote: null`, a string, and the key absent parses under each; the first provider call of the gated replay is the live acceptance check, and a schema-level 400 stops it before spend accrues. The `.extend`-at-call-site fallback is chosen from what that inspection observes, not assumed; `tests/provider-contract-enforceable.test.mjs` still passes. Negative control: a prompt mentioning a field the schema lacks fails the same check.
- **Old and non-LLM rows stay valid**: a finding without the three fields parses under both schemas; a finding with `lineStart: null` parses.
- **Identity pin** (Risk 2), red-then-green.
- **Resolver**: unique, multi-line, CRLF, ambiguous, not-found, missing file, sensitive file, path escape; each status asserted.
- **Deterministic fixture control (in `npm test`, any checkout)**: a temp git repo with committed before/after files and known hunks, covering anchored-in-hunk, anchored-outside-hunk, dirty file, missing blob, insertion/deletion/rename/shift. **Historical control** (integration, needs the two commits): git range `66b91739..c2d62f6b`, `scripts/lib/llm-budget.mjs`; when the objects are absent it reports `skipped (objects absent)` loudly and fails under `REQUIRE_HISTORICAL_RANGE=1`: findings whose `lineQuote` is copied from a real post-image line inside a real hunk, resolved by the resolver, fed to `reopenRate`: `measured: true`. Same findings with an absent quote: `measured: false`. A quote copied from a line OUTSIDE every hunk: measured, not counted as reopened.
- Seed stability snapshots updated knowingly (`PASS_PROMPTS` is byte-pinned by existing tests).

**Replay on stored rounds (needs provider calls; GATED).** Replaying ~10 stored rounds through the new prompt requires the model to emit the quote, so it is not free. It does not run until the coordinator has the cost estimate (computed from the stored per-pass token usage of the chosen rounds, section 7) and says go. Rounds are chosen among those with a stored `audited_sha` (since #473) and a known fix range. Report: fraction of findings with a quote, fraction resolved (`anchored`), fraction of anchored round-N findings inside a real post-image hunk of the SAME range production uses, `auditedSha(N-1)..auditedSha(N)` (the code round N re-flagged after the round N-1 fixes); the replay metric and the production signal share one definition, with insertion, deletion, rename and shifted-line controls on the temp fixture, and the `[lines]` status mix.
- **Coverage is reported, not hidden.** `reopenRate` is "measured" when at least one finding is located (the consumer contract, unchanged). So each checkpoint also reports located / total findings and the unlocated reasons, and the replay compares located vs unlocated findings by severity and pass to expose a biased locatable subset. A control fixture where only one low-severity finding of ten is locatable must show up as `located 1/10` in the report, not as a clean "measured".
- **Success** = `reopenRate` measured on >= 70% of real round-3 checkpoints in the replay set (today ~0%), AND the report shows the located share per checkpoint so Louis can judge it; a result where most measured checkpoints locate under a third of their findings is reported as `measured-but-thin`, with the call on a minimum-coverage gate left to the signal owner (see section 8).
- **Replay harness** (gated): per selected round, an isolated `git worktree` at that round's recorded `audited_sha` (checkout, not the current tree); the input scope is RECONSTRUCTED from the recorded range, not from where findings landed: changed files = `git diff --name-only auditedSha(N-1)..auditedSha(N)` filtered by the same scope rules the audit applies (`audit-scope.mjs`), so files that produced no finding are included; a round missing either sha or whose scope rules cannot be re-applied is excluded and counted (test: a fixture round with an input file that yields no finding); the pass is run through the real renderer and resolver against that checkout, so rendering and resolution share one snapshot. A round whose commit is missing, or whose stored scope cannot be recovered, is EXCLUDED and counted; the exclusion count is reported before any success percentage is computed. Below that the signal stays advisory and the plan reports why (status mix tells whether it is no-quote, not-found or ambiguous).
- A stored-data-only floor is reported without spend: of the existing findings, how many have a `file:N` already (the 0.9%), so the lift is attributable to the new field.

## 7. Acceptance criteria

1. Emitted-schema, identity, resolver and positive-control tests pass in `npm test`; `npm run check` green.
2. `citedLocation` and `round-signals.mjs` are byte-identical to main.
3. Replay cost estimate (stored token usage x current model prices, labelled `derived`) sent to the coordinator; replay result section appended to this plan if approved and run, or "NOT RUN: awaiting cost approval" if not.
4. `/audit-code` converged with the Gemini final gate; audited head == HEAD; nothing pushed.

## 8. Not done (scope boundary)

A minimum-location-coverage gate inside `reopenRate` (the coordinator fixed the consumer contract for this plan; the replay's located-share report is the evidence for deciding it later); Pilot 1 scope and T2 threshold recalibration (separate); store columns for lines; tie-breaking an ambiguous quote by changed hunk (the `[lines]` status mix says whether it is worth building); Option A's persisted extraction (read-side fallback exists).
