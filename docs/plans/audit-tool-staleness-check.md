# Plan — Consumer-side audit-tool staleness check (Option A)

**Status**: implemented 2026-05-13.
**Owner**: Louis.
**Origin**: 24-hour stretch where three sync-related blockers (PR 39, 55, 56 in
wine-cellar-app) traced to consumer repos running stale `claude-engineering-skills`
audit-tool files. Surface "your audit-tool is stale" before the audit
silently produces out-of-date findings.

---

## Problem

Consumer repos (wine-cellar-app, ai-organiser, ...) install the audit-tool
by syncing files from `claude-engineering-skills`. Coders working in consumer
repos have no in-band signal when upstream ships a new audit-tool revision
that includes their files. The current symptom is `ERR_MODULE_NOT_FOUND` or
mysteriously-different audit findings.

User chose **Option A** from a three-way: a consumer-side staleness check
that fires on `/audit-code` startup. Warning is **non-blocking** (audit
continues) but loud (named files listed, fix command shown). Manifest is
generated by the source repo during `npm run sync` and pushed to GitHub
where consumers fetch it.

---

## Components

### 1. `scripts/lib/sync-manifest.mjs` (new)

Pure logic. Five exports:

- `hashFile(absPath)` → `'sha256:' + sha256-hex`. SHA-256 over file bytes.
- `computeFileHashes(rootDir, files)` → `{ [relPath]: hash }`. Skips
  `scripts/.sync-manifest.json` itself (recursive hashing) and any path
  that doesn't exist on disk.
- `generateManifest(rootDir, files, opts)` → object with
  `{ generatedAt, repo, branch, commitSha, files }`. `commitSha` resolved via
  `git rev-parse HEAD` inside `rootDir`; null on failure.
- `writeManifest(rootDir, files, opts)` → calls `generateManifest`, writes
  the result to `scripts/.sync-manifest.json` (pretty-printed JSON, trailing
  newline).
- `compareToUpstream(localRoot, upstreamManifest)` → `{ stale[], missing[],
  current, upstreamCommit, upstreamGeneratedAt }`. Stale = local hash differs
  from upstream. Missing = file absent locally.
- `fetchUpstreamManifest(url?, { timeoutMs? })` → Promise resolving to the
  parsed manifest. Default URL: `https://raw.githubusercontent.com/Lbstrydom/claude-engineering-skills/main/scripts/.sync-manifest.json`.
  Override via `AUDIT_TOOL_MANIFEST_URL` env. 3s default timeout; HTTP !=200
  rejects with `HTTP <code> fetching <url>`. Uses node's built-in `https`
  (no extra deps).
- `isSourceRepo(rootDir)` → boolean. Reads `package.json` and checks for
  `name === 'claude-engineering-skills'`. Returns false on any read error.

### 2. `scripts/check-audit-tool-version.mjs` (new)

Standalone CLI. Flags: `--json`, `--quiet`. Env: `AUDIT_TOOL_VERSION_CHECK=skip`
short-circuits to exit 0. Source-repo detection short-circuits to exit 0
(verdict `SOURCE_REPO`). Network failure → exit 2 (verdict `NETWORK_ERROR`).
Stale → exit 1 (verdict `STALE`, JSON includes `stale[]` and `missing[]`).
Current → exit 0 (verdict `CURRENT`).

Human-readable mode emits a box-drawn warning with upstream commit, file
list (capped at 10 per category), and fix instructions.

### 3. `scripts/openai-audit.mjs` (modified)

Inside `main()`, right after the model-catalog-refresh block, inline the
staleness check. Constraints:

- 2.5s timeout (tighter than CLI's 5s — never delay audit startup).
- Skipped when `process.env.CI` is truthy.
- Skipped when `AUDIT_TOOL_VERSION_CHECK=skip`.
- Skipped via `isSourceRepo()` when running from claude-engineering-skills itself.
- Network errors swallowed silently (never block audit on network).
- Stale state surfaces a single warning paragraph to stderr — does NOT exit.
  Format: `[sync-check] WARNING: N audit-tool file(s) differ from claude-engineering-skills @ <sha>`.
- Implemented as `await import('./lib/sync-manifest.mjs')` to keep the cost
  off the hot path when the check is disabled.

### 4. `scripts/sync-to-repos.mjs` (modified)

Two changes:

- Static import: `import { writeManifest } from './lib/sync-manifest.mjs'`.
- Before the target-repo loop (after the dry-run banner), call
  `writeManifest(SOURCE_ROOT, [...CORE_SCRIPTS, ...ARCH_MEMORY_SCRIPTS], { repo: 'Lbstrydom/claude-engineering-skills' })`.
  Skipped when `--dry-run` is passed.
- Add to `CORE_SCRIPTS`:
  - `scripts/check-audit-tool-version.mjs`
  - `scripts/.sync-manifest.json`
  - `scripts/lib/sync-manifest.mjs`

### 5. `scripts/.sync-manifest.json` (generated, committed)

Generated artefact. Committed to git so it's accessible via
`raw.githubusercontent.com`. Excludes itself from hashing.

### 6. `package.json` (modified)

Add `sync:version-check` script: `node scripts/check-audit-tool-version.mjs`.

### 7. `skills/ship/SKILL.md` (modified)

Add Step 6.0 between Step 5.5 and Step 6.1. Contents: regenerate manifest
in source repo via `node scripts/sync-to-repos.mjs --target wine` (any
target works; manifest writes first), then stage `scripts/.sync-manifest.json`.
Skip in consumer repos.

## Acceptance criteria

1. From claude-engineering-skills root: `node scripts/check-audit-tool-version.mjs --json`
   emits `{"verdict": "SOURCE_REPO"}` and exits 0.
2. From a consumer repo, with upstream manifest unreachable: emits
   `{"verdict": "NETWORK_ERROR", "error": "..."}` and exits 2.
3. From a consumer repo, with upstream manifest present and matching local
   files: emits `{"verdict": "CURRENT", ...}` and exits 0.
4. `node scripts/sync-to-repos.mjs --target wine` regenerates the manifest
   as its first action; output line begins `manifest  scripts/.sync-manifest.json @ <sha>`.
5. `openai-audit.mjs` in a consumer repo with stale files prints
   `[sync-check] WARNING: ...` to stderr but completes the audit normally.
6. `AUDIT_TOOL_VERSION_CHECK=skip node scripts/openai-audit.mjs ...` shows
   no sync-check output at all.
7. `CI=1 node scripts/check-audit-tool-version.mjs` — does NOT skip (CLI is
   manually invoked). Only `openai-audit.mjs`'s inline check honours CI.
   (Actually: deliberate design — CLI is for explicit checks; inline check is
   advisory.)
8. Manifest excludes itself from `files` (no recursive hashing).
9. Manifest captures all CORE_SCRIPTS + ARCH_MEMORY_SCRIPTS — currently 101 files.

---

## Non-goals

- Auto-syncing consumer repos. Manual `npm run sync` from source repo is
  still required; check is advisory only.
- Blocking audits on stale state. Warning only; user decides.
- Detecting LOCAL-only modifications (consumer edited their own copy).
  System treats any hash mismatch as "stale" — fine for first cut.
- Cross-repo write access (Option C). Out of scope.
- Manifest signing / cryptographic provenance. Out of scope.

---

## Risk register

| Risk | Mitigation |
|---|---|
| Network outage delays audit startup | 2.5s timeout; failure swallowed silently |
| Upstream manifest 404 (first push hasn't happened) | Network error path: silent in openai-audit, exit 2 in CLI |
| Consumer modified files locally → false stale | Acceptable for v1; user dismisses with env var |
| Recursive hashing of manifest in itself | Excluded explicitly in `computeFileHashes` |
| Manifest one commit behind reality (pre-push hook generates it post-commit) | /ship Step 6.0 regenerates BEFORE staging, ensuring commit includes the manifest |
